# Wan World Model GRPO (OpenVLA-OFT on LIBERO)

Reinforcement-learning fine-tuning of [OpenVLA-OFT](https://github.com/moojink/openvla-oft)
with **GRPO**, where the training environment is the **Wan action-conditioned
video world model** — the policy is optimized on "imagined" rollouts generated by
Wan, with **no physics simulator and no real robot in the training loop**.
Evaluation is run in the real LIBERO simulator for ground-truth task success.

## Overview

| Aspect | Value |
|--------|-------|
| **Framework** | RLinf v0.3 |
| **Algorithm** | GRPO (group_size 8) |
| **Training env** | Wan world model (LIBERO-Spatial), `env_type: wan_wm` |
| **Eval env** | Real LIBERO-Spatial simulator (ground-truth success) |
| **Policy** | OpenVLA-OFT (continuous action head) |
| **World model** | `RLinf/RLinf-Wan-LIBERO-Spatial` (Wan2.2 VAE + DiT + `resnet_rm.pth` reward model) |
| **Compute** | 1x p5en.48xlarge (8x H200 141GB) |
| **Venv** | `openvla-oft` |
| **Config** | `wan_libero_spatial_grpo_openvlaoft` |

Unlike a physics simulator, the Wan world model has no `reset()`: it generates
future RGB frames `[B, 256, 256, 3]` conditioned on the current observation, a
7-D action sequence, and a natural-language task prompt. The training reward is a
world-model reward classifier output in `[0, 1]`. Initialization frames are
bundled in the Wan checkpoint (`.../dataset/`), so no separate dataset download
is required for training.

A Hugging Face token is optional but **recommended** for the downloads: create a
`hf-token` Secret (`kubectl create secret generic hf-token --from-literal=HF_TOKEN=hf_...`)
to avoid anonymous per-IP rate limits.

## Deploy

```bash
export ECR_URI=$(terraform -chdir=infrastructure/build output -raw ecr_repository_url)
export NAMESPACE=<your-namespace>

# 1. Stage the Wan world model + OpenVLA-OFT policy to FSx
envsubst '${NAMESPACE}' < examples/wan-openvlaoft-grpo/manifests/model-download.yaml | kubectl apply -f -

# 2. Launch GRPO training (single node, 8 GPUs)
envsubst '${ECR_URI} ${NAMESPACE}' < examples/wan-openvlaoft-grpo/manifests/wan-openvlaoft-grpo.yaml | kubectl apply -f -

# 3. Watch training progress + env/success_once
kubectl logs -n ${NAMESPACE} -l job-name=rlinf-wan-openvlaoft-grpo -f
```

For a short smoke run, append `runner.max_steps=2` to the `HYDRA_OVERRIDES` value
in the training manifest. Keep the shipped config's batch math intact (do not
resize `total_num_envs`).

## Validation

> **Validated on EKS.** This deployment was run end-to-end on Amazon EKS (1x
> p5en.48xlarge, 8x H200): a short 2-step GRPO run completed successfully (Job
> `SUCCEEDED`), exercising the full pipeline — OpenVLA-OFT policy load, Wan
> world-model environment init, GRPO rollout generation through the world model
> (16 rollout epochs/step), and the GRPO actor update (all 8 GPUs at ~100% util).
> This validates the machinery, not task accuracy; a 2-step run is a smoke test.
> For real accuracy, train for many more steps. Use this as a starting point for
> your own runs.

Notes for reproduction:
- The training image installs the Wan diffusion library `diffsynth`
  (diffsynth-studio) into the `openvla-oft` venv (handled by the unified image).
- The training manifest sets `env.train.enable_offload=False` (the Wan env's
  offload method isn't detected through the env-wrapper stack; disabling env
  offload runs fine on p5en H200).
